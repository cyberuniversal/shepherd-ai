# Week 2 Data Collection Protocol

## Purpose

Week 2 needs real command data before stronger training claims are possible. The existing dataset is synthetic and useful only for pipeline development. This protocol defines how to collect human-written commands, recorded WAV commands, gold transcripts, and intent labels without mixing them with synthetic examples.

## Data Types

Use explicit `data_type` values:

- `synthetic_command`: self-authored or model-generated command text.
- `human_written_command`: command text written by a human participant.
- `human_recorded_audio`: WAV audio recorded by a human participant.
- `human_verified_transcript`: transcript checked against a human recording.
- `asr_transcript`: transcript generated by a speech recognition model.

Do not label model-generated text as human-written.

## Typed Command Collection

Collect typed commands as JSONL records under `datasets/commands/`.

Required schema:

```json
{
  "id": "human_cmd_001",
  "text": "Send two drones north and inspect the crops.",
  "split": "train",
  "source": "human_written_collection_v1",
  "data_type": "human_written_command",
  "expected_intent": {
    "action": "inspect",
    "count": 2,
    "location": "north",
    "target": "crops",
    "constraints": []
  }
}
```

Allowed intent fields for Week 2:

- `action`: normalized mission action such as `inspect`, `scan`, `send`, or `return`.
- `count`: integer, `"all"`, or `null`.
- `location`: normalized language location such as `north`, `south`, `east`, `west`, or `null`.
- `target`: normalized mission target such as `field`, `crops`, `greenhouse`, `irrigation canal`, `drones`, or `null`.
- `constraints`: list of constraint phrases extracted from the command.

## Audio Collection

Record commands as WAV files under `datasets/sample_audio/`.

Required manifest schema:

```json
{
  "id": "audio_001",
  "audio_path": "datasets/sample_audio/audio_001.wav",
  "transcript": "Send two drones north and inspect the crops.",
  "source": "self_recorded_collection_v1",
  "data_type": "human_recorded_audio",
  "split": "validation"
}
```

Record collection notes separately in `reports/`, including:

- Recording device.
- Microphone distance.
- Environment noise level.
- Speaker accent/language notes, if voluntarily provided.
- Whether the transcript is first-pass human, corrected human, or ASR-generated.
- Consent and privacy notes.

Do not commit private audio or identifiable participant information.

## Splits

Use fixed splits before training:

- `train`: model fitting only.
- `validation`: feature/model selection only.
- `test`: final held-out evaluation only.

Do not duplicate normalized command text across splits. Do not tune feature settings using the test split.

For the next small collection, use at least:

- 30 human-written commands for training.
- 10 human-written commands for validation.
- 10 human-written commands for test.
- 10 WAV recordings with verified transcripts before running ASR evaluation.

These are not final research sample sizes; they are the minimum useful Week 2 expansion.

## Evaluation Flow

1. Validate labeled command JSONL with `load_labeled_commands`.
2. Train on `train` only with `scripts/train_intent_model.py`.
3. Inspect validation metrics and field-level errors.
4. Freeze the selected model configuration.
5. Evaluate the frozen model on test with `scripts/evaluate_intent_model.py`.
6. Validate WAV manifests with `load_audio_manifest`.
7. Evaluate ASR transcripts separately from intent extraction.
8. Evaluate intent extraction on gold transcripts and ASR transcripts separately.

## Collection Commands

Fast path: collect one typed command and optional WAV recording in one command:

```powershell
python scripts/collect_week2_sample.py `
  --text "Send two drones north and inspect the crops." `
  --wav "C:\path\to\your_recording.wav" `
  --split train
```

This copies the WAV into `datasets/sample_audio/`, appends `datasets/sample_audio/manifest.jsonl`, and appends `datasets/commands/human_written_commands_draft.jsonl`.

Important: records created by `collect_week2_sample.py` use `data_type: human_written_command_draft_labeled` and a parser-versioned `label_source` such as `deterministic_v1_draft`. Older draft records may show `deterministic_v0_draft`. The command text and audio can be human-provided, but the intent labels are parser drafts. Review labels before treating them as human-verified ground truth.

Append one labeled typed command to a collection JSONL file:

```powershell
python scripts/create_command_record.py `
  --output datasets/commands/human_written_commands.jsonl `
  --id human_cmd_001 `
  --text "Send two drones north and inspect the crops." `
  --split train `
  --source human_written_collection_v1 `
  --data-type human_written_command `
  --action inspect `
  --count 2 `
  --location north `
  --target crops
```

Validate and summarize a command dataset:

```powershell
python scripts/validate_command_dataset.py `
  --dataset datasets/commands/human_written_commands.jsonl `
  --summary-output outputs/evaluations/human_written_commands_summary.json `
  --require-splits train,validation,test
```

Validate and summarize an audio manifest:

```powershell
python scripts/validate_audio_manifest.py `
  --manifest datasets/sample_audio/manifest.jsonl `
  --dataset-root . `
  --summary-output outputs/evaluations/audio_manifest_summary.json
```

Audit the collected Week 2 files before training:

```powershell
python scripts/audit_week2_collection.py `
  --commands datasets/commands/human_written_commands_draft.jsonl `
  --audio-manifest datasets/sample_audio/manifest.jsonl `
  --dataset-root . `
  --output outputs/evaluations/week2_collection_audit.json
```

The command examples above are workflow examples only. Do not commit `human_written_commands.jsonl`, `manifest.jsonl`, or audio files unless the records are real, provenance is documented, and privacy/licensing requirements are satisfied.

## Research Integrity Rules

- Keep synthetic, human-written, human-recorded, and ASR-generated records distinguishable.
- Preserve failed runs and negative results.
- Record model name, version, package version if applicable, random seed, parameters, data split, and artifact paths.
- Raw outputs belong in `outputs/evaluations/`.
- Analysis and interpretation belong in `docs/` or `reports/`.
- Do not report real-user or speech performance until human or audio datasets exist.
